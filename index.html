The problem as the ministry sees it

The instruments are getting more precise. The paperwork isn't keeping up.

OIML R‑76 lays out, in exact detail, how a non‑automatic weighing instrument must be tested before it's approved for trade use — eccentricity, repeatability, discrimination threshold, tare, temperature effect, and more, each with its own tolerance band per accuracy class. Empanelled labs already run these tests correctly.

What slows a problem statement like this one down is everything that happens after the test: transcribing readings, looking up the right maximum permissible error for the instrument's class and capacity, and laying the results out in the exact R‑76‑2 / R‑76‑3 report format the ministry expects — by hand, per instrument, per lab, every time.

That manual step is where transcription errors creep in, where report formats drift between labs, and where a backlog builds up between a test bench and a certificate a trader can actually use.

01Each accuracy class (I, II, III, IIII) carries its own MPE and scale‑interval rules — easy to mis‑apply by hand.
02R‑76 test reports must follow a fixed international layout, so ministry and trading‑partner reviewers can read any lab's certificate the same way.
03A single instrument type can be tested at dozens of empanelled labs — with no shared, live view of pass rates or turnaround time.
04Paper and static PDF certificates are simple to photocopy and alter, with no easy way for a buyer to check one is genuine.

How VeriScale fits into a lab's existing workflow

The test bench doesn't change. Everything after it does.

A technician still runs the instrument through the R‑76‑1 Annex A/B test sequence exactly as they do today. VeriScale takes over the moment a reading is recorded.

Step 1
Test bench
Standard test weights, the instrument under test, and the technician running the existing R‑76‑1 procedure.
Step 2
Data capture
Readings come in from a digital indicator, or are entered by hand with range and unit checks built in.
Step 3
Compliance engine
Applies the correct MPE and scale‑interval rules for the instrument's declared accuracy class, and flags anything out of tolerance.
Step 4
Report & certificate
Builds the R‑76‑2 / R‑76‑3 formatted report, ready for the reviewing officer's signature and a scannable verification code.

What's actually in the system

Six modules, each doing one job well

Digital test capture
MODULE 01
Pulls readings straight from a digital indicator over USB or serial, or takes manual entries for standard test weights, checking each one against the expected range for that test step as it's entered.
Compliance engine
MODULE 02
Encodes the R‑76‑1 Annex A and B tolerance tables for accuracy classes I, II, III and IIII, so every eccentricity, repeatability, discrimination and temperature‑effect result is checked against the right maximum permissible error automatically.
Auto report builder
MODULE 03
Lays test results out in the R‑76‑2 test report and R‑76‑3 type‑evaluation formats the ministry already recognises, so a reviewer sees the same structure whichever lab it came from.
Tamper‑evident certification
MODULE 04
Each issued certificate is hashed and given a scannable code, so a buyer, dealer, or ministry official can check in seconds whether a certificate matches what was actually issued.
Multi‑lab oversight dashboard
MODULE 05
Gives the ministry a live view across every empanelled lab: test volumes, pass and fail rates by instrument type, and reports still waiting on review.
Works without steady internet
MODULE 06
Captures and validates test data on the device first, and syncs to the central system once a connection is back — built for labs outside major cities.

Beyond the hackathon build

Where this goes after the report is solved

Continuous field monitoring

IoT‑enabled instruments could report drift data over their working life, so a recalibration is scheduled before an instrument fails a spot check in the field.

Beyond NAWI

The same compliance engine can be extended to other OIML recommendations — R51 for catchweighing instruments, R60 for load cells — without rebuilding the report pipeline.

Predictive service life

A history of test results per instrument could support an estimate of remaining accurate service life, useful for both owners and inspecting officers.

One national ledger

Integrating with state Controller of Legal Metrology systems would give the ministry a single, searchable record of every certified instrument in the country, not just those tested through VeriScale.
